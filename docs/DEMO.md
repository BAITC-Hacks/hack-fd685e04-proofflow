# Демо ProofFlow: 3 минуты

Сценарий использует **только синтетический набор** из кнопки «Загрузить демо». Он
показывает работу расчёта, а не выдаёт искусственно добавленные идентификаторы
клиентов или периоды отсутствия товара за сведения Электрокомплекта.

| Время | Действие | Что доказать |
| --- | --- | --- |
| 0:00–0:20 | Открыть локальное приложение, выбрать «Загрузить демо», показать 10 SKU и отметку «синтетические данные». | Запуск без API-ключа, интернета и частной подписки. |
| 0:20–0:50 | Нажать «Рассчитать», открыть позицию с сезонным спросом и затем позицию с устойчивым ростом. | Прогноз по датам, сезонный коэффициент и тренд в объяснении, не статическая таблица. |
| 0:50–1:20 | Открыть SKU с явно заданным интервалом отсутствия товара и SKU с разовым крупным заказом. | Отдельно видны восстановленный спрос и исключённый аномальный объём. Уточнить: в партнёрских файлах этих полей нет; это проверка поведения на синтетике. |
| 1:20–1:50 | Сравнить позиции с ранним и поздним поступлением. Под рекомендациями раскрыть «Данные и параметры товаров» или нажать «Данные» в навигации. Изменить остаток или срок поставки и пересчитать. | Датированное поступление влияет на размер рекомендации; изменение исходных данных меняет результат. |
| 1:50–2:20 | Показать группировку по поставщикам, срочность, количество и краткое объяснение на строке. | Менеджер видит, что и почему предлагается заказать. |
| 2:20–2:45 | Изменить количество, «Утвердить заказ» от имени проверяющего, скачать CSV/XLSX и «Паспорт расчёта». | Сохранены рекомендация и решение человека; JSON содержит сверку и отпечаток. Система не отправляет заказ поставщику сама. |
| 2:45–3:00 | Переключить светлую/тёмную тему и RU/KK/EN; для новых серверных пояснений выполнить новый расчёт. | Выбор сохраняется в браузере. Экспорт использует язык расчёта. |

Перед показом выполнить из корня репозитория:

```powershell
.\.venv\Scripts\python.exe scripts/preflight.py
.\.venv\Scripts\python.exe scripts/verify_live_flow.py
.\.venv\Scripts\python.exe server.py
```

Проверочный скрипт сам запускает временный localhost-сервер с отдельной базой;
последняя команда запускает рабочую демонстрацию на http://127.0.0.1:8000.
Не заменять реальный расчёт заранее сохранённым скриншотом. Если загрузка ZIP
занимает заметное время, открыть реальные данные заранее и при показе объяснить
время/объём импорта, не выдавая его за мгновенный.

Реальные данные показывайте отдельным дополнением. Панель покрытия данных
отражает подтверждённость входных полей, не точность прогноза. Неизвестная цена
помечается, общий бюджет может быть неполным. Если остаток или срок поставки
не подтверждены, утверждение требует проверки параметров или явной отметки
согласия с ограничениями. Клиентские ID и точные stockout-интервалы в исходных
книгах отсутствуют; не приписывайте им синтетические поля демо.

Правки количества сначала нужно утвердить, чтобы они вошли в экспорт и паспорт.
После утверждения новый вариант создаётся новым расчётом. «Параметры» раскрывают
политики категорий; «Шаблон JSON» рядом с источником скачивает синтетический набор.
SHA-256 паспорта позволяет сравнить версии и не является цифровой подписью.

Короткая формулировка для жюри: «ProofFlow собирает черновики закупок по
поставщикам, учитывая историю спроса, сезонность, рост, остатки и дату поставок.
Рекомендация объяснима и меняется вместе с исходными данными. Решение об
утверждении остаётся за сотрудником. Неизвестные поля не подменяем догадками».
