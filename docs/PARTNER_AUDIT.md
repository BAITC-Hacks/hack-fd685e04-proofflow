## Покрытие входов технического задания

| Вход | Фактическое состояние | Правило ProofFlow |
| --- | --- | --- |
| Дата, SKU, количество продаж | Есть в обеих дневных выгрузках. | Можно рассчитывать спрос и сезонность после очистки дат/возвратов. |
| Склад продажи | Есть, но в обеих дневных выгрузках только «Алматы». | Не утверждать многоскладскую историю продаж на основании этих файлов. |
| Анонимный клиент | **Нет**. Есть номер документа. | Не называть документ клиентом. Допустима проверка разового **заказа/события** с отдельной оговоркой; клиентские повторы по этим данным не доказуемы. |
| Цена транзакции | **Нет** в дневных таблицах. `СС реал` в другом отчёте имеет неуточнённую семантику. | `unit_price` и денежный итог нельзя считать подтверждёнными; нужен отдельный прайс/согласование. |
| Текущий остаток | Месячные матрицы до сентября 2026; для Systeme есть отдельные колонки доступного/резервного остатка. | Уточнить дату среза, сеть против склада, резерв и единицы; не складывать итоговые и складские колонки. |
| Точное время stockout | **Нет** интервалов начала/конца. Месячный нулевой остаток не доказывает дни без товара. | Не имитировать реальные потерянные продажи; механизм проверять на синтетическом кейсе или после отдельной выгрузки. |
| Поставка в пути | IEK: количественные партии с плановыми ETA; Systeme: колонка «в пути 24.09». | ETA учитывать по дате только при подтверждённой интерпретации поля. |
| Срок поставщика `lead_days` | **Нет** подтверждённого SLA. | Оставить явно редактируемым; `ETA` существующей партии не является lead time нового заказа. |
| MOQ и кратность | Есть **кратность/минимальный разряд отгрузки**. | `pack_size` можно предложить как маппинг; отдельный MOQ требует подтверждения. |
| Категория и коэффициент роста | Есть в Systeme `TDSheet`; в IEK явной SKU-категории не обнаружено. | Коэффициенты применять только после проверки их определения и масштаба; для IEK политика категории не может быть заявлена как исходное поле. |
| Материальная ведомость / прямой обмен 1С | Есть коды 1С в ряде файлов, но схема регистра, API и документа «Заказ поставщику» не предоставлена. | Файловый пилот, не заявлять готовый коннектор/автоматическое проведение в 1С. |

Обязательные для пилота уточнения у партнёра: дата и границы остатков,
правила возвратов, источник периодов stockout, анонимный ключ клиента (если
клиентские аномалии важны), SLA поставщиков, настоящий MOQ, смысл `СС реал`,
дата `24.09` и соответствие складских колонок. Без них синтетический тест
доказывает функцию алгоритма, но не точность соответствующих рекомендаций на
реальных данных.
