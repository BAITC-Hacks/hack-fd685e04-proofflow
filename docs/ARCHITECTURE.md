# Архитектура ProofFlow

ProofFlow — однопользовательский локальный сервис поддержки закупщика. Главная
функция — воспроизводимый расчёт черновика заказа, а не чат-бот и не генерация
заранее подготовленного ответа. Python 3.12+, FastAPI, SQLite, статический
HTML/CSS/JS; при расчёте нет вызовов облачных моделей или платных API.

```text
JSON / CSV / локальные книги XLSX или ZIP     Синтетический пример
                 │                                  │
                 └──────── importer.py ────────────┘
                              │ канонический набор + предупреждения
                              ▼
                    storage.py (SQLite, локально)
                              │
                ┌─────────────┴──────────────┐
                ▼                            ▼
       quality.py (полнота)         engine.py (чистый расчёт)
                                             │
                                             ▼
                                результат + разбор по SKU/складу
                                             │
                frontend/ ◀──── server.py ────┤
                                             ▼
                              решение человека → exports.py → CSV/XLSX
                                             │
                                             └→ evidence.py → JSON паспорт решения
```

## Границы модулей

| Модуль | Ответственность | Не делает |
| --- | --- | --- |
| `importer.py`, `partner_xlsx.py` | Парсинг известной схемы, нормализация, сообщения о пропусках; обезличивание входных идентификаторов перед дальнейшей обработкой. | Не выводят несуществующий `client_id` из номера документа; не превращают отсутствующие stockout/lead time в измеренные факты. |
| `engine.py` | Детерминированный прогноз, очистка выбросов, сезонность/тренд, потерянный спрос при наличии интервалов, остаток/поступления, кратность, объяснения. | Не хранит данные, не вызывает сеть и не утверждает заказ. |
| `quality.py` | Отчёт по полноте и происхождению значимых полей. | Не подменяет верификацию первичных данных у владельца 1С. |
| `storage.py` | Локальное сохранение набора, прогонов и решения человека в SQLite. | Не синхронизирует данные с облаком. |
| `server.py` | HTTP-контракт, локальный preview, запуск расчёта, выбор строки, явное утверждение, отдача файлов. | Не предоставляет многопользовательскую авторизацию и не отправляет заказ поставщику. |
| `exports.py` | CSV/XLSX после расчёта, защита недоверенного текста от формул. | Не проводит документ в 1С. |
| `evidence.py` | Сверка исходных и утверждённых количеств, полноты цен и локальный SHA-256 отпечаток JSON-паспорта. | Не удостоверяет личность, истинность источников или неизменность записи. |
| `frontend/` | Рабочее место менеджера, группировка по поставщикам, просмотр обоснования; `lib/money.js` пересчитывает отображаемые суммы после правок до ответа сервера. | Не рассчитывает рекомендуемое количество: оно определяется сервером. Отображаемая сумма не подменяет серверное утверждение и экспорт. |

## Два режима проверки

1. **Демо.** Синтетический набор содержит известные эффекты, позволяющие
проверить реакцию на stockout, всплеск, изменение остатка и ETA. Он не
выдаётся за данные партнёра.
2. **Реальные файлы.** Адаптер читает только распознанные книги и листы,
показывает неполноту схемы. Партнёрские файлы остаются локально и не входят
в Git. Отсутствие анонимного ключа клиента, дат stockout и SLA поставщика
ограничивает доказательную силу расчёта. Рекомендация по реальным материалам
должна проверяться менеджером до утверждения.

## Риски и масштабирование

Текущая топология рассчитана на локальный пилот и демонстрацию, не на общий
публичный сервер. Перед промышленным развёртыванием потребуются аутентификация
и роли, изоляция данных организаций, управляемое хранилище, резервное
копирование, журнал доступа, согласованный контракт 1С и SLA с владельцем
данных. Не публикуйте текущий порт в интернет. Вместо неограниченной отдачи
всей истории браузеру API возвращает компактный результат, а подробные ряды
запрашиваются по отдельной позиции.
