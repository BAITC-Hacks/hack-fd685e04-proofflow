# ProofFlow: приемка по кейсу Электрокомплект

Источник: предоставленное команде ТЗ «Автоматический расчёт заказов поставщикам
для пополнения склада» (трек 05, задание 01). Эта матрица не заменяет ТЗ и
не обещает балл жюри. Статусы сверены с кодом и агрегированным локальным
замером **23.09.2026 около 16:30 UTC+5**; после новых изменений их следует
перепроверить. Зелёный тест на синтетике доказывает поведение алгоритма, но
не достоверность отсутствующих полей партнёрского источника.

| Требование ТЗ | Текущая реализация и доказательство | Статус / остаётся проверить |
| --- | --- | --- |
| Must have 1: история продаж, остатки, товары в пути, категории, рост влияют на количество по артикулу | `engine.calculate`; направленный `tests/test_acceptance.py::test_every_quantitative_must_have_input_changes_a_recommendation` меняет каждый численный источник отдельно; `tests/test_engine.py` проверяет датированный приход; `tests/test_partner_xlsx.py` проверяет соединение книг по коду 1С | **Механизм и локальный импорт подтверждены.** Распознаны 3 588 SKU, 248 467 положительных продаж и 313 поступлений. Остатки/ETA требуют подтверждения смысла у партнёра. Категория влияет через настраиваемые `growth`/`safety_days`, не через догадку о коэффициенте в XLSX. |
| Must have 2: сезонность и устойчивый рост | Дневной/месячный коэффициенты и десезонализированный тренд в `engine.py`; тесты `test_seasonality_is_non_neutral_and_future_date_specific`, `test_stationary_seasonal_peak_is_not_double_counted_as_growth`, `test_isolated_client_order_spike_removed_but_sustained_growth_retained` | **Синтетика подтверждена; дневная история партнёра импортируется.** Фактическую прогнозную точность на отложенном периоде ещё не измеряли; месячные контрольные отчёты не складываются повторно с дневными продажами. |
| Must have 3: упущенный спрос во время отсутствия товара | Явные интервалы `stockouts`; `tests/test_engine.py::test_explicit_stockout_imputes_lost_demand_and_raises_recommendation` | **Синтетика подтверждена.** Нельзя утверждать компенсацию по реальному архиву, пока в нём не найдены даты stockout; не выводить их из нулевых продаж без проверки. |
| Must have 4: исключение разового крупного заказа, включая одного клиента | Порог + концентрация на обезличенном клиенте или событии; `tests/test_engine.py::test_isolated_client_order_spike_removed_but_sustained_growth_retained`, `test_event_id_can_flag_one_off_order_without_claiming_customer_identity` | **Механизм подтверждён на синтетике; реальный прогон пометил 858 исключённых событий.** Среди них 517 SKU требуют ручной проверки документных пиков. `event_id` не клиент: для полноценной проверки «один клиент» нужен его обезличенный ID. |
| Must have 5: список по поставщикам с объяснением каждой позиции | `supplier_groups`, `rows[].explanation`, `breakdown`; `tests/test_acceptance.py::test_same_sku_isolated_by_warehouse_and_grouped_by_supplier`, `tests/test_engine.py::test_supplier_groups_and_explanations_match_real_calculation` | **API/ядро подтверждены.** HTTP-слой нормализует отсутствующего поставщика как `UNASSIGNED` перед повторной группировкой. Финальную визуальную проверку интерфейса выполнить отдельно. |
| Сценарий менеджера: склад/категория → список → проверить/исправить → утвердить | Фильтры и endpoints в `server.py`, SQLite approval в `storage.py`; `tests/test_end_to_end.py` проверяет цикл demo–calculate–detail–approve–export | **API частично подтверждён; UI ещё не подтверждён визуально.** Нужна проверка после завершения фронтенда; утверждение не должно маскировать черновик. |
| Выход: артикул, поставщик, количество, причина, срочность, экспорт | `engine.py`, `exports.py`; `tests/test_acceptance.py::test_export_is_a_flat_reviewable_csv_and_xlsx_not_a_sent_order` | **CSV/XLSX структура подтверждена на синтетике.** Точная схема импорта в 1С партнёра не предоставлена, следовательно совместимость с их учётной системой **не проверена**. Нужен образец/подтверждение партнёра; до тех пор это универсальный ручной экспорт. |
| Приватность и обезличивание клиентов | Локальный bind, некоммитируемое хранилище, отказ от отправки поставщикам; `importer.py` и `server.py` HMAC-псевдонимизируют `client_id`/`event_id` перед хранением и вычислением, включая прямой `POST /api/calculate`; тесты API/импортёра | **Прежний прямой риск закрыт в HTTP-потоке.** Псевдонимизация не заменяет анонимизацию на стороне источника и аутентификацию; проект остаётся однопользовательским локальным пилотом. |
| Не отправлять заказ без подтверждения | В коде нет отправки поставщикам; экспорт черновика помечен, после approval отдельный файл; `tests/test_api.py` и `tests/test_acceptance.py` | **Подтверждено в текущем коде.** Сам экспорт по-прежнему ручная операция сотрудника, не автосенд. |
| Устойчивость к аномалиям, плохим входным данным | Валидация объёмов, дат и дубликатов; лимиты на загрузку, горизонт, количество строк и распаковку; `tests/test_partner_xlsx.py` проверяет схемы и безопасный путь ZIP | **Локальный реальный импорт и расчёт заняли 23.899 с** (16.319 с + 7.580 с); 527 предупреждений не скрываются. Это один замер без HTTP/UI/SQLite и без пикового RAM, не гарантия для произвольных вредоносных файлов. |
| README: методология, выбросы, запуск | `README.md`, `docs/METHODOLOGY.md`, `docs/DATA_MAPPING.md`, `requirements.lock`, `scripts/preflight.py` | **Документы и локальное окружение имеются.** Перед сдачей повторить preflight на текущем коммите и ручной запуск по README; Docker на этой машине не проверен. |
| Репозиторий и сдача на платформе | Код ведётся в официальном team repo; `docs/SPRINT.md` фиксирует два часовых инкремента | **Не финализировано.** Коммит/push не заменяет нажатие «Сдать решение». Проверить репозиторий, README, ссылку и форму платформы до freeze. |

## Минимальная финальная приемка

1. `.\.venv\Scripts\python.exe scripts/preflight.py` на текущем дереве, затем
   отдельный запуск UI по README; системный Python может не иметь `openpyxl`.
2. Повторить реальный импорт обоих архивов партнёра и сверить агрегированные
   счётчики/предупреждения без публикации клиентских строк или самих файлов.
3. Изменить в UI каждый источник из Must have 1; продемонстрировать три
   диагностических примера: сезонность, stockout, разовый заказ.
4. Проверить ручную коррекцию количества, авторство утверждения, скачивание
   CSV/XLSX и невозможность автоматической отправки поставщику.
5. Подтвердить ограничения 1С и пропущенных входных полей в README/демо;
   не обещать интеграцию, которую не проверяли с владельцем задачи.
6. Подтвердить push в официальный репозиторий и отдельную сдачу через платформу.
